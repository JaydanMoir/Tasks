# Задачи

Список задач с напоминаниями. Одна кодовая база работает и как веб-приложение,
и как нативное приложение для iPhone (Capacitor + WKWebView).

## Структура

```
index.html, css/, js/     собственно приложение (без сборщика, чистые ES-модули)
scripts/build-www.mjs     собирает www/ — то, что уезжает внутрь iOS-бандла
ios/                      Xcode-проект, сгенерирован Capacitor
capacitor.config.json     appId, имя приложения, webDir
```

Зависимости ставятся только для сборки iOS. Веб-версия ни в чём из `node_modules`
не нуждается — её можно открыть с любого статического сервера.

## Разработка в браузере

```bash
python3 serve.py            # http://localhost:8765, без кеширования
```

Правки в `js/` и `css/` подхватываются перезагрузкой страницы, сборка не нужна.
После обновления зависимостей один раз выполните `npm run build`, чтобы в корне
появился `capacitor.js` — без него страница ругнётся 404 на этот скрипт
(в браузере он не обязателен, но лишняя ошибка в консоли мешает).

## Сборка приложения для iPhone

Требуется Xcode и Node. Node лежит в `~/.local/node` — добавьте его в `PATH`:

```bash
export PATH="$HOME/.local/node/bin:$PATH"
```

Дальше:

```bash
npm install          # один раз
npm run sync         # собрать www/ и перенести в Xcode-проект
npm run open:ios     # открыть проект в Xcode
```

`npm run sync` нужно повторять после каждой правки веб-части — Xcode держит
собственную копию файлов внутри бандла.

В Xcode: выберите таргет **App** → вкладка *Signing & Capabilities* → укажите
свою команду разработчика (Team). Затем подключите iPhone кабелем, выберите его
в списке устройств и нажмите Run.

С бесплатным Apple ID подпись действует 7 дней, после чего приложение перестаёт
запускаться и его нужно установить заново. Данные при переустановке сохраняются.

## Как устроены уведомления

Это единственное место, где веб и приложение расходятся по-настоящему.

В браузере напоминания работают опросом: `fireReminderNotifications` раз в 20
секунд спрашивает у хранилища, не наступило ли время. Пока вкладка закрыта, не
срабатывает ничего — для телефона это бесполезно.

В приложении всё наоборот. `js/notifications.js` заранее отдаёт будущие
срабатывания системе через `UNUserNotificationCenter`, и дальше их показывает
уже iOS — с закрытым приложением, без интернета, без работающего процесса.

Расписание пересобирается целиком (а не по разнице) при каждом изменении задач и
при возвращении в приложение. Правила разложения:

| Задача | Как ставится |
|---|---|
| без даты, на сегодня, на вечер, просроченная | ежедневный триггер на время напоминания |
| с датой в будущем | разовый триггер на эту дату |
| с предварительным напоминанием | отдельное уведомление за N минут |
| «повторять каждые N минут» | серия разовых до конца суток, не больше шести |
| «когда-нибудь» | не ставится вовсе |

## Резервные копии

Все данные лежат в `localStorage` веб-вью — одной JSON-строкой под ключом
`tasksApp.v1`, внутри песочницы приложения. Переустановка поверх их не трогает,
удаление приложения — стирает.

Выгрузка копии тоже расходится по платформам. В браузере это обычная ссылка со
скачиванием; в приложении так нельзя — WKWebView не сохраняет файл по
`<a download>` с blob-ссылкой, нажатие просто ничего не делает. Поэтому там файл
пишется во временный каталог и отдаётся системному листу «Поделиться».

Ежедневные напоминания намеренно занимают один слот вместо копии на каждый день:
у iOS жёсткий предел в 64 ожидающих уведомления на приложение. Если задач с
напоминаниями окажется больше, лишние отсекаются по дальности — ближайшие
срабатывания важнее.
